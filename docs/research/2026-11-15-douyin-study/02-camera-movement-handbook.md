# AI短剧运镜设计与提示词手册

抖音作品观察与软件设计基础  2026年11月15日

我们的软件应先让用户决定这个镜头要交代什么，再把机位、景别、运动路径、主体动作和落幅写成可编辑的结构。只提供“电影感”“大师运镜”按钮，无法解释生成失败，也难以保持镜头之间的连续性。

### 阅读范围与证据口径

本手册整理50条去重的抖音作品，涵盖运镜教学、图文方法、操作演示与生成案例。研究方式是打开作品，抽看可见视频片段、屏幕字幕或图文正文，并记录来源；不代表逐条完整观看或听写全部讲解。我们未据此实际生成视频，也未验证作者关于模型效果、速度或成功率的宣传。

附录逐条给出观察层级与具体要点。正文中的 C 编号对应附录来源。“软件建议”“检查规则”和原创示例属于我们基于观察所做的设计推导，仍需用真实生成任务验证。

### 先落实的四项能力

1 结构化镜头表  先填叙事任务，再填机位、景别、运动和起止画面。

2 起止状态预览  每条运镜显示起幅、落幅和经过节点，让用户能看懂镜头要去哪里。

3 角色动作与相机分轨  人走向哪里、相机怎么走分别描述，控制复杂度。

4 成功镜头可复用  保存参考图、提示词版本与结果，单独重做失败镜头。

### 如何使用本手册

先用第2页区分术语，再用第3至4页填写镜头；第5至6页用于衔接与检查，第7页转成开发任务。附录保留50条作品的入口与观察记录，便于后续回看和补充实测。

## 镜头类型与叙事用途

本批多条作品反复把机位、景别和运动分开讲解。它们描述的是不同维度，应在界面和数据中分别保存。C08、C13、C18、C23。

景别回答“主体占多大”，机位回答“从哪里看”，运动回答“相机位置或朝向怎样变化”，时间效果回答“动作与相机如何随时间变化”。例如，平视是机位，中景是景别，跟拍是运动；三者可以组合。

| 镜头 | 适用任务 | 填写重点 |
| --- | --- | --- |
| 固定 | 观察表演或等待反应 | 固定位置与朝向 主体可动 C02 |
| 推进 | 集中注意或放大情绪 | 从中景到近景的落幅 C01 C08 |
| 后拉 | 显露环境或表现疏离 | 新出现的背景信息 C19 |
| 摇镜 | 由一个目标转向另一个 | 机位不移 朝向改变 C13 |
| 横移 | 建立空间层次或关系 | 方向 路径 前景视差 C05 C18 |
| 跟拍 | 伴随角色行进 | 相对位置 距离 同速 C06 C10 C21 |
| 升降 | 逐层揭示人物或环境 | 高度变化与揭示顺序 C01 C07 |
| 环绕 | 强调登场或双人关系 | 中心 方向 角度 落幅 C13 |
| 手持 | 紧张或现场感 | 抖动幅度 画面仍可读 C20 |
| 变焦 | 改变画幅而不必移动机位 | 与推进区分 是否联动 C03 |
| 第一视角 | 让观众进入角色视线 | 视线方向 可见身体部位 C15 |
| FPV穿越 | 奇观和快速空间穿梭 | 障碍 路径 速度变化 C11 C17 |

## 可填写的单镜头工作表

把一个镜头写成一个可执行任务。无需每次填满专业参数，但必须让人能判断起幅、动作、相机运动与落幅是否相容。C06、C07、C08。

| 字段 | 填写内容 |
| --- | --- |
| 镜号与场景 | 镜号____ 场景____ 角色资产____ 预计时长____秒 |
| 镜头任务 | 观众在这一镜要发现什么或感受到什么____ |
| 起幅 | 景别____ 机位____ 主体位置____ 前中后景____ |
| 主体动作 | 谁在____时间做____ 动作终点____ |
| 相机运动 | 固定或____ 从____沿____到____ 速度____ |
| 焦点计划 | 起始对焦____ 是否转移焦点____ 何时转移____ |
| 落幅 | 结束景别____ 角色姿态____ 视线方向____ |
| 连续性 | 必须保持的脸 服装 道具 布局 光线____ |
| 衔接 | 前镜结束____ 本镜开始____ 后镜接____ |
| 验收 | 关键时刻____ 可接受偏差____ 失败后优先改____ |

### 写作顺序

先写主体与场景，再写主体动作，随后描述相机起点、路径、速度和终点；最后列一致性条件。长镜头按经过的地点分节点，记录入口、出口与高度，不能只罗列场景名。C27、C32。

### 静态图与视频指令分别保存

静态分镜图主要决定人物、环境、光色、构图与材质。视频指令在已锁定的图上继续交代动作和相机随时间的变化。软件应保留两份提示词，防止修改运镜时顺带改掉服装或场景。C04、C23。

## 路径速度与焦点的写法

### 把笼统形容词改成可观察的变化

| 笼统写法 | 更可检查的表达 |
| --- | --- |
| 高级慢推 | 平视中景开始 持续5秒推进到胸像近景 最后停稳 |
| 丝滑跟拍 | 相机位于角色侧后方约1米 与角色同速前行 保持画幅占比 |
| 震撼环绕 | 以人物为中心从正面向右侧绕行90度 落在侧面中近景 |
| 逐渐揭示 | 从鞋尖近景开始 依次显露衣摆和上身 落在半身构图 |
| 前景擦过 | 相机横移 前景门柱短暂遮住主体 焦点保持在中景人物 |

这些是我们改写的表达示例，借鉴的是结构，未复制作者完整提示词，也未做生成效果承诺。C05、C06、C07、C10。

### 原创示例一 情绪慢推

傍晚旧院，人物坐在木椅上，望向画面右侧院门。平视中景起幅，相机在5秒内沿直线缓慢推进至胸像近景，速度均匀，最后半秒停稳。人物只轻轻握紧手中的布袋，保持目光方向。焦点留在眼睛，背景院门和树的位置不变。

检查近景是否增加了情绪信息，是否出现多余转头或环境漂移。

### 原创示例二 随行发现

角色沿走廊向前走，相机位于其侧后方，以相同速度跟随4秒。前景门框从画面左侧擦过，逐步显露走廊尽头的空椅；角色停下时，相机同步减速停稳，结束在角色与空椅同框的中景。

检查同速跟随与显露空椅能否同时完成；不稳时先简化遮挡。

焦点计划也要独立填写。C31的环绕加移焦案例同时出现前景人物、纸币和背景人物。借此可把“相机到哪里”与“观众此时看清谁”分开控制，并为焦点切换标注时点。

## 镜头衔接与空间连续性

运镜设计需要看前后镜头。C22展示从章节、场景到节拍的分层组织，C24把转场理解为隐藏切点。这支持我们在软件里同时保存镜头任务和结束状态。

### 每次切镜先核对五件事

1 人物  身份、发型、服装、手中道具和动作进度是否连贯。

2 空间  门窗、桌椅、树和主要光源的位置是否相容，可使用共同空间锚点。C28。

3 方向  前镜人物的移动、视线和出画方向，能否接到后镜。

4 时间  动作是继续、重复、跳时，还是进入回忆，是否有清楚依据。

5 注意力  切镜后首先看到的对象，是否承接上一镜的动作或线索。

### 轴线与视线作为软件检查建议

对双人对话，先在场景图中标出两人位置及其连线，再记录相机位于连线哪一侧。普通正反打尽量保持双方银幕朝向稳定；跨越轴线若有意为之，应加入可理解的过渡镜头或明确标记。此处属于拟加入的电影连续性规则，不能据本次抽看片段断言已由50条作品逐项验证。

### 四种转场需要的前后状态

| 类型 | 前镜与后镜要匹配的内容 |
| --- | --- |
| 遮挡转场 | 遮挡物覆盖画面时切换 再由相容遮挡显露新画面 |
| 甩镜转场 | 方向和运动模糊相容 避免突然逆向或静止 |
| 动作匹配 | 动作阶段 方向 速度及主体位置尽量接续 |
| 相似构图 | 关键形状或主体占位相似 同时让时间地点变化可理解 |

C24为这四类提供作品正文依据。上表是供开发和验收使用的解释性归纳。转场不是每镜必选项；对话和动作衔接清楚时，直接切换通常更容易控制。

## 提示词冲突与失败处理

| 冲突或问题 | 处理方式 |
| --- | --- |
| 固定机位 同时围绕人物旋转 | 明确选择固定或环绕；若只是主体转身，移到角色动作字段 |
| 推近又拉远 但没有联动说明 | 拆成不同阶段；需要变焦联动时启用明确模板 |
| 主体与相机都剧烈运动 | 先减少其中一项的复杂度，保留叙事必要的动作 |
| 落幅中人物必须很小又必须看清微表情 | 拆成环境镜与反应近景，避免相互争夺画幅 |
| 镜头越过墙体或物体无故消失 | 重画路径或增加经过节点；检查参考场景空间 |
| 人物遮挡后换脸 服装改变 | 减少遮挡与转身幅度；检查参考资产与起止帧 |
| 字幕说环绕 实际只是画面缩放 | 按可见结果复核运动类型，不能只信提示词名称 |
| 每条镜头都在动 情绪反而散乱 | 回到镜头任务，给反应和停顿保留固定或停稳段 |

### 先修最小问题

保留成功镜头，只修改失败片段；一次优先改一个控制量，例如时长、动作或路径。C34记录作者多次用纯提示词尝试后，拼接位置仍难一致的经验。这支持保留失败样本，并为复杂空间增加白模辅助。

### 生成后人工检查顺序

先看动作是否正确，再看主体与场景是否连续，随后判断镜头运动是否符合叙事。最后再检查画面闪烁、模糊、变形以及音画时序。画质好并不自动说明镜头设计合格。

### 不要把作者宣传写成产品承诺

“一条提示词直接出大片”“完美还原”“任何模型都能用”等话术只记录为作者主张。我们的软件应显示具体模型、输入素材、提示词版本、结果和失败原因。只有同条件实测后，才统计成功率或费用。C10、C16。

## 软件字段与首轮验证

建议先实现一张可填写、可预览、可版本追踪的镜头表。高级轨迹和白模功能可以后加，但底层数据应允许保留路径节点与参考资产。C04、C09、C12、C18。

| 字段组 | 建议保存的内容 |
| --- | --- |
| 叙事与资产 | shot_id scene_id beat_id purpose character_refs scene_ref |
| 起始取景 | start_framing camera_height camera_angle subject_position |
| 相机计划 | movement path_nodes duration speed_profile end_framing |
| 表演与焦点 | subject_action_timeline focus_target focus_change |
| 连续与衔接 | stable_assets screen_direction end_state transition_to_next |
| 生成与审阅 | provider model prompt_version result_ref review_status retry_reason |

### 第一轮软件验收

1 选择三种基础镜头：固定、慢推、侧后跟拍。用同一角色和同一场景分别生成小样，检查差异是否可辨。

2 为一组双人对话设置三个机位，检查站位、视线和桌椅位置；记录人工能发现但程序未发现的问题。

3 选择一种遮挡转场，给出明确前后状态；保留失败样本，归纳哪类遮挡或运动最容易失稳。

4 记录提交、等待、生成、重试和人工审阅时间。把一次成功与多次挑选后的成功分开统计。

### 评价尺度

分别评价叙事清晰、运动符合、角色连续、空间稳定、动作完成、画面完整六项，用通过、需修改、不可用并写原因。价格和速度单独记录。输入的距离、角度和时长是意图，并非模型精确执行的证明。
