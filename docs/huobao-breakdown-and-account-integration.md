# Huobao 功能拆解与已有账号接入设计

日期：2026-11-15，北京时间。适用工程：AI-Drama-Studio。Huobao 参考版本：v4.0.11，提交 `b48e6b2312166e25b1ff141832d2e82e5d63c142`。

产品目标是让用户通过已有账号、已安装的官方工具或网页协作完成短剧工作，默认无需填写 API Key、服务地址和模型代号。应用负责组织项目资料、制作任务、候选结果和版本；账号连接能做到的自动化程度、使用额度和支持的媒体能力分别核实。

本文件是后续开发的设计输入，表格中的目标行为按后续计划实施。拆解采用的本地初版快照覆盖故事立项工作台和本机 Codex 创作说明扩写。上传前核对 GitHub 基线 `b9b6aa152c04dc1234e4dee8b2705ecca6905363` 后，确认远端已更新到 0.2.1，增加剧本输入、即梦任务适配、不可变稿件版本和 Codex 独立审阅；即梦生成仍因费用待确认而未提交。初版的功能范围不能当作远端当前范围，后续设计应复用这些新增实现。当前能力以 [README](../README.md)、[第二阶段说明](https://github.com/499893181-lang/AI-Drama-Studio/blob/b9b6aa152c04dc1234e4dee8b2705ecca6905363/docs/stage2.md) 和 [首次业务验收](https://github.com/499893181-lang/AI-Drama-Studio/blob/b9b6aa152c04dc1234e4dee8b2705ecca6905363/docs/first-business.md) 为准；[初版架构](architecture.md)、[工具检查](tool-inspection.md) 和 [历史验收](validation.md) 保留其各自适用范围。正式四岗位发布、媒体生成和视频导出仍属待整合能力。

1. **把 Huobao 拆成制作流程和执行工具两层。** 项目、分集、角色、场景、道具、分镜和任务构成作品管理；大模型、图片模型、视频模型和 FFmpeg 执行具体工作。更换执行工具时，前一层的作品结构仍然保留。Huobao 的价值主要在于把这些对象和任务关联起来。[项目说明](https://github.com/chatfire-AI/huobao-drama/blob/v4.0.11/README.zh-CN.md)

| 顺序 | Huobao 的用户操作和内部实现 | 我们吸收的设计 |
| --- | --- | --- |
| 1 | 新建项目，保存名称、画风和画幅；项目中建立分集 | 一个作品包含多集；每集有目标时长、制作要求和进度，保留原始构思 |
| 2 | 粘贴小说或原文，调用改写 Agent，原文与剧本分开保存 | 保留原稿，先产生候选和差异；用户采用后形成新版本 |
| 3 | 从剧本提取角色、场景、道具，并与项目已有资产匹配 | 稳定实体 ID、人物关系、事实来源和锁由正式策划继承；发现新事实交回责任阶段 |
| 4 | 依据描述、风格生成资产提示词；生成或上传参考图 | 资产卡保存文字设定、参考图版本和来源；参考图确认后再用于后续镜头 |
| 5 | 把剧本拆成镜头，绑定角色、场景、道具和时长 | 同一结构化分镜生成可读表格、首帧提示词和运动提示词；锁定项贯穿逐镜 |
| 6 | 为镜头准备参考素材、首尾帧和图片／视频提示词 | 发送前预览任务包，明确哪个镜头、哪版输入、哪些实际附件被发送 |
| 7 | 提交生成任务，查询进度，下载结果并回写镜头 | 作品对象和生成尝试分开；每次尝试保存独立任务号、输入版本和产物 |
| 8 | 恢复中断视频任务或重试结果下载 | 优先查询已有任务；只有明确重新生成才创建新任务，避免重复消耗额度 |
| 9 | 勾选已有镜头，按镜号拼接 MP4，保存合成历史 | 支持部分预览和最终导出；导出前实测尺寸、时长、帧率与音轨 |
| 10 | 界面显示阶段进度、任务抽屉、预览和失败原因 | 分开显示草稿、检查、制作和实际文件状态，用户能定位卡在哪一步 |

流程实现可沿以下源码逐项核对：[剧本工具](https://github.com/chatfire-AI/huobao-drama/blob/v4.0.11/backend/src/agents/tools/script-tools.ts)、[资产提取](https://github.com/chatfire-AI/huobao-drama/blob/v4.0.11/backend/src/services/extraction.ts)、[分镜工具](https://github.com/chatfire-AI/huobao-drama/blob/v4.0.11/backend/src/agents/tools/storyboard-tools.ts)、[生成与恢复](https://github.com/chatfire-AI/huobao-drama/blob/v4.0.11/backend/src/services/generation.ts)、[拼接导出](https://github.com/chatfire-AI/huobao-drama/blob/v4.0.11/backend/src/services/ffmpeg-merge.ts)。

本版已审的生产链没有独立 TTS、字幕制作和完整剪辑时间线；角色可上传音色参考，部分声音来自视频模型。我们将配音、字幕、混音和后期验收列为独立模块，分别验证能力，不能依据宣传截图就标记已经实现。[移除 TTS 的官方结构测试](https://github.com/chatfire-AI/huobao-drama/blob/v4.0.11/backend/tests/remove-audio-tts-structure.test.mjs)

2. **把 Huobao 的数据组织转换成我们的作品结构。** 它使用项目级资产，在分集和镜头中通过关联复用；生成任务代表一次执行尝试，不能充当角色或分镜本身。[数据结构](https://github.com/chatfire-AI/huobao-drama/blob/v4.0.11/backend/src/db/schema.ts)

| 对象 | 主要关系 | 我们需要保存的内容 |
| --- | --- | --- |
| 作品与分集 | 一个作品有多集，每集引用当前正式版本 | 原始需求、集次、目标时长、画幅、版本索引 |
| 角色／场景／道具 | 在项目中定义，多集复用，逐镜引用 | 稳定 ID、来源、锁定状态、允许变化、参考素材版本 |
| 剧本与分镜 | 段落承接节拍，镜头承接段落、时间和实体 | 台词动作、起终态、世界空间、声音时间线 |
| 生成尝试 | 一次尝试对应一版输入和一个执行来源 | 任务 ID、连接器、状态、外部任务号、错误、原始响应 |
| 素材 | 同一镜头可有多次生成和多个候选 | 文件哈希、来源、被选版本、实测时长、检查结果 |
| 导出记录 | 固定一次导出所使用的素材与版本 | 镜头顺序、音轨／字幕、参数、实际文件和检查记录 |

应用的 `data/projects/<UUID>.json` 继续保存界面草稿和索引。正式故事事实由 `projects/<project_id>/brief.md` 及各阶段规定文件负责。新增工作区适配层将界面项目映射到正式项目；界面索引不再复制一套具有独立修改权的角色和剧情事实。

3. **保留我们已有的四岗位流程，再接媒体制作。** 六段创作说明只是正式 brief 的候选材料；扩写成功表示收到了有效候选，不能等同策划 PASS。远端第二阶段的剧本任务和独立审阅也不能替代这里规定的完整四岗位发布链。

```mermaid
flowchart LR
    A[用户需求与创作说明] --> B[策划与统一设定]
    B --> C[时间轴剧本]
    C --> D[视觉设定与分镜]
    D --> E[独立最终审稿]
    E --> F[图片与视频制作]
    F --> G[配音字幕剪辑]
    G --> H[媒体验收与导出]
```

| 岗位 | 应用要读取和展示的正式内容 | 进入后续流程的依据 |
| --- | --- | --- |
| drama-topic | brief、选题卡、统一设定、自检、交接 | 当前 topic verify、PASS、无阻断和有效交接 |
| drama-script | 有效策划输入、时间轴剧本、自检、交接 | 实际运行 topic verify 与 script verify |
| drama-visual | 有效上游、视觉设定、结构化分镜、图片／运动提示词、自检、交接 | 实际运行三个生产阶段 verify |
| drama-review | 当前 15 份输入、独立问题和责任回退 | 三个上游有效、独立审查完成、自检和当前交接有效 |
| 媒体与后期 | 当前前期包、真实生成文件和实际检查结果 | 前期包仍有效；实际媒体另做检查和验收 |

审稿阶段遇到门禁失败、缺件或损坏时，仍须生成 `outputs/04-review/` 的四份规定文件，结论为 REVISE、`handoff_ready=false`，列明责任和不可审范围。这类正式审稿计入最多两次额度；诊断读取不能越过失效交接。

阶段检查、修正次数和最终审稿额度继续由项目账本管理。三个生产阶段各自首检为 0，最多修正并复检 1／2 两轮；最终独立审稿最多两次。旧账本缺失时，从有效正式报告导入可证明的预算下限，不能默认为 0。额度耗尽后停止对应自动循环。切换账号、模型、自动／手工方式、任务号或运行目录都不重置额度。上游变更后按依赖关系使旧结论失效。传输恢复与正式内容修正分别记录；发生内容修正和正式复检时按既有规则计数。岗位只改自身负责的文件。这些设计约束来自本地短剧制作工作区的 `AGENTS.md` 及对应岗位技能；该工作区约定尚未作为完整四岗位功能部署在此软件仓库中，整合时须逐项承接，不能只根据界面状态发布正式包。本文件不另行定义账本或生产文件格式。

4. **“免填 API Key”和“免费使用模型”是两项不同目标。** 用户可以通过官方账号授权免去手工配置，但程序内部仍需要受支持的调用接口；额度可能来自套餐、赠送额度或开放平台钱包。产品将显示真实的额度来源，不把未取得的费用数据填成零。

| 连接方式 | 用户操作 | 自动化范围 | 当前适用判断 |
| --- | --- | --- | --- |
| 本机官方 CLI | 在官方工具登录一次，在工作台选择使用 | 公开命令支持的任务，可接收真实结果 | 当前已实现 Codex 的创作说明扩写 |
| 官方账号授权 | 点击连接，在官方网页完成登录与授权 | 账号允许的模型和操作 | ChatGPT 有官方路线；DeepSeek Harness 有账号路线候选 |
| 网页协作 | 软件准备任务，用户在官网发送，再导入回答 | 任务准备、导入和校验可自动；发送与取回需用户操作 | 覆盖豆包、DeepSeek、ChatGPT 的通用后备方案 |
| 厂商／网关 API | 用户自行配置或管理员提供 | 接口允许的任务 | 作为可选扩展，默认流程不要求填写 |

OpenAI 当前官方文档提供 Sign in with ChatGPT：符合条件的 Plus／Pro 用户可授权应用使用套餐所含或可用积分支持的请求。公开的账号额度接入指南适用于开源、本机托管应用；付费或远程托管产品需另行申请。我们保留现有 Codex CLI 路线，并把原生账号授权作为待接入能力。授权成功不代表全部模型或全部媒体功能可用。[接入概览](https://developers.openai.com/siwc/quickstart)、[开源及本机应用条件](https://developers.openai.com/siwc/token-sharing-open-source)

此授权不会读取用户既有 ChatGPT 对话；产品仍需明确发送当前项目资料。当前预览路线不支持图像生成工具、转写和音视频输入，因此先用于符合条件的文字任务；图片和视频制作仍需各自连接器或手工导入。[当前预览限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

DeepSeek 官方 Harness 存在通过系统浏览器登录的账号插件和独立的账号模型路由。它关联 `platform.deepseek.com` 的账号和钱包，不应描述成复用 `chat.deepseek.com` 免费聊天权益。官方 CLI／SDK 有程序化结果通道，但账号路由与 headless／SDK 的具体接线、账号资格和额度必须单独实测。设计状态设为“官方文档支持，待集成验证”。[账号插件](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/credentials/deepseek-account/README.md)、[账号模型路由](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/llm-deepseek-account/README.md)、[CLI 通道](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/cli/README.md)

豆包已公开应用插件、用户授权和 MCP 接入，主要方向是用户在豆包内让豆包调用我们的工具。它可以成为另一个产品入口，但这些文档不足以证明独立桌面软件可直接使用普通豆包账号进行通用推理。默认先做网页协作；宿主内插件列为需平台准入和审核的后续路线。[豆包应用插件登录接入](https://open.doubao.com/apps-plugin/docs/backend-development/login)

网页／桌面自动操作、浏览器扩展可作为后续实验路线，须逐站点验证公开能力、用户授权及适用条款，单独标为实验功能。它们不作为首版稳定自动调度的依赖；登录和人机验证由用户处理，产品不通过读取 Cookie、截取登录令牌或逆向私有接口冒充官方连接。

5. **把用户界面从模型参数表改为工作分配。** 首页设置展示“我的创作工具”，普通用户先选择谁来完成哪类工作，技术参数放在可选的高级设置中。

| 用户看到的卡片 | 首版操作 | 必须同时显示的信息 |
| --- | --- | --- |
| 本机 Codex | 检测工具、使用当前登录、执行支持的文字任务 | 登录方式、已验证能力、最近一次真实任务结果 |
| ChatGPT | 网页协作；后续增加官方账号授权 | 当前协作方式；官方授权模式下的套餐授权、可用模型、额度不足和撤销状态 |
| DeepSeek | 网页协作；后续增加 Harness 账号连接 | 聊天网页与平台账号路线分开，平台钱包不是免费聊天额度 |
| 豆包 | 复制任务、打开官网、导入结果 | 明确标为需用户操作，不显示“自动连接成功” |
| 图片／视频创作工具 | 上传素材、导入结果；已验证工具另列自动入口 | 支持的输入、是否已登录、是否会消耗积分、实际任务状态 |

每个岗位可选择不同工具，例如策划用网页 DeepSeek、编剧用已登录 Codex、审稿用另一轮独立任务。账号可选不等于角色权限可绕过；所有来源都走相同的候选、检查和发布链。

额度用尽时显示原因和可选动作：等待额度恢复、换已连接工具、转网页协作、手工编辑。不能暗中切换到付费 API。显示“额度未知”时，系统不能声称正在执行账户级预算硬限制。正式发送前按连接器说明确认发送的项目内容及实际附件；文件只存了名称时不能声称模型已读附件。

6. **用统一任务包衔接自动调用和网页协作。** 网页协作的流程应尽量压缩，但要保留用户主动发送和导入两个动作。

```mermaid
flowchart LR
    A[选择岗位和当前有效输入] --> B[准备任务包]
    B --> C[复制提示词并打开官网]
    C --> D[用户发送并取得回答]
    D --> E[粘贴或导入结果]
    E --> F[格式与版本检查]
    F --> G[候选预览及差异]
    G --> H[采用并进入岗位检查]
```

以“把策划扩写成剧本”为例，软件先验证策划交接，再准备完整约束、稳定实体 ID、节拍、时长和所需输出格式。用户点“复制任务”并“打开豆包”，在官网粘贴发送。返回工作台后点“导入回答”；软件显示原始回答、缺失字段和冲突，用户核对候选，之后由 drama-script 的规定流程完成正式检查与发布。

任务包至少绑定项目 ID、分集、岗位、输入版本／哈希、任务要求、事实锁、允许变化、所需输出格式及实际附件清单。较大的上下文可下载为文件包，由用户在官网上传；网站上传和上下文限制不适合当前任务时，提示换工具或缩小任务，不能静默丢弃约束。

导入回答先原样保留，再确定性解析。格式不合格时展示具体字段问题，不默默改写故事以获得通过。语义判断与格式验证分开；模型写出的“PASS”是普通文本，不能充当本地 guard 结果。自动格式修复若需要再次调用模型，要形成可见任务，不伪装成纯本地解析。

| 返回结果 | 接收办法 | 后续处理 |
| --- | --- | --- |
| 文字或 JSON | 粘贴文本／导入文件，保存原文和来源声明 | 检查结构、稳定 ID、锁和输入版本，形成候选 |
| 图片 | 用户选择真实文件并关联资产或镜头 | 保存文件和哈希，检查尺寸、内容连续性与来源 |
| 视频／音频 | 用户导入实际文件并关联生成任务 | 用 FFprobe 读取实际参数，检查时长、音轨和同步 |
| 外部任务仍在运行 | 有公开任务查询能力时保存任务号；否则等待用户 | 超时显示状态未知或等待导入，不自动再次提交 |

用户手工声明的来源平台和模型名按“用户声明”记录，不冒充服务端核验；自动连接器则记录返回的模型、请求号和工具版本。剪贴板只在用户点“复制／导入”时读写，不后台持续监听。

7. **任务完成、结果合格和阶段通过分别显示。** 连接和认证只证明能够尝试发送，不能代表整个生产链可用。

| 状态维度 | 可使用的状态 | 关键判定 |
| --- | --- | --- |
| 工具／授权 | 未安装、待登录、已登录、授权不足、连接失败 | 每次使用前检查当前条件；已登录仍可能额度不足 |
| 能力证据 | 未核实、文档支持、命令已检测、真实任务已验证 | 分别记录文字、读图、生图、生视频等能力 |
| 执行任务 | 待发送、等待用户、运行中、等待导入、已收到、失败、取消、中断、状态未知 | 真实事件驱动，不模拟生成进度 |
| 候选结果 | 原始导入、格式合格、语义待审、待采用、已采用、输入过期 | 有结果不等于已采用或审查通过 |
| 正式阶段 | 未开始、REVISE、当前有效 PASS、交接失效 | 由规定文件、实际 verify、哈希和账本共同决定 |
| 媒体 | 待生成、已导入、待检查、通过、需重做 | 实际文件存在且检查完成，才可进入最终交付 |

网络断开后，支持公开查询的连接器先恢复原任务。没有可查询证据的发送保留“状态未知”，让用户核实后决定是否重发。下载重试不创建新的生成任务。取消本地等待不表示远端任务必然已取消或已退还额度。

8. **连接器向工作流提供统一能力，隐藏技术参数。** 业务模块请求“依据这版策划写剧本”，连接器负责把任务交给已选工具；返回仍是待校验候选。

| 能力入口 | 职责 | 首轮实现范围 |
| --- | --- | --- |
| detect／getCapabilities | 报告安装、授权和逐项能力证据 | 复用现有工具探测；网页协作明确 manual |
| prepareTask | 读取当前有效输入，形成任务包与发送预览 | 新增通用任务包构建器 |
| connect／disconnect | 官方登录、授权和解除连接 | 本机工具由官方程序管理认证；原生 OAuth 后续接入 |
| submit／observe／cancel | 提交、订阅／查询和尽力取消任务 | 保留现有 Codex 实现；不支持者不暴露自动发送 |
| importResult | 接收用户主动导入的原文和实际媒体 | 新增候选导入，统一校验和差异展示 |
| publishCandidate | 将候选交给责任岗位检查与发布 | 由工作区适配层调用现有岗位规则 |

新的统一结果记录可保存 `jobId`、`connectorId`、`mode`、`stage`、`inputRevision`、`inputHashes`、`externalTaskId`、`rawResultPath`、`candidatePath`、`evidence` 和 `usageSource`。这里只定义应用任务记录；各岗位正式 JSON、账本与交接单仍沿用对应技能的现有格式。账号凭据由官方工具或系统安全存储管理，任务记录不放令牌。

支持模型选择时，选项绑定具体连接器／账号配置和模型，避免只用模型名造成同名渠道混淆。仅列出该连接器实际报告或验证的模型与能力；不能把一个平台上全部模型名称当作当前账号都有权限使用。

10. **按可验收的顺序扩展现有软件。** 下表是设计整合的优先顺序。0.2.1 已有的稿件版本、任务适配和独立审阅应复用并补齐通用能力；先把外部协作和候选保护做完整，后续再增加官方账号连接与媒体能力。

| 开发次序 | 交付内容 | 完成标准 |
| --- | --- | --- |
| A | “我的创作工具”、岗位工具分配、任务包、复制提示词、打开官网、原文导入 | 不要求新 API Key；用户能用已有聊天产品完成一次真实文字协作 |
| B | 通用候选、差异、事实锁、版本冲突和来源记录 | 改输入后拒绝旧候选覆盖；导入失败保留原文和正式稿 |
| C | 工作区适配层，依次接入四岗位 | 实际调用 guard 和账本；预算不因连接器或任务切换重置；失效输入不能跨阶段发布 |
| D | 现有 Codex 文字任务扩展，随后验证 ChatGPT 官方授权与 DeepSeek Harness 账号路线 | 按账号显示真实模型与额度来源，逐项完成真实调用和失败分支验证 |
| E | 资产、分镜媒体导入，以及已验证工具的生成与恢复 | 真实文件、任务号、版本和镜头关联完整；未知状态不自动重复提交 |
| F | 配音、字幕、时间线、媒体检查与导出 | 实测声音和字幕同步、尺寸时长、输出完整性，提供实际可播放成片 |

各步骤需要覆盖的关键场景包括：未登录、拒绝授权、额度不足、任务取消、网络中断、导入格式错误、输入变更、人工锁冲突、修正额度用尽、失效交接、媒体缺失和导出规格不一致。只有文档或帮助存在的连接器不能显示为“真实任务已验证”。

初版 `src/codex.mjs` 已有官方 CLI 调用、完成事件和格式检查；`src/store.mjs` 已有 revision、输入哈希和候选采用保护。0.2.1 另有剧本存储、任务、官方工具适配和独立审阅模块，应以当前源码核对扩展位置。历史扩写或某次独立审阅成功不代表完整四岗位、其他账号或媒体能力已验证。设计阶段不需要为验证说明而反复提交模型或媒体生成任务。
