# 第二阶段独立Codex剧本审阅

`src/script-review.mjs` 提供 `ScriptReviewJobs`，只在用户显式发起审阅后调用真实本机Codex。构造服务、读取剧本或查看历史不会触发审阅。它不修改创作说明、剧本正文或用户项目，不把即梦生成成功当作剧情审阅通过。

## 输入与独立性

每次新开独立 `codex exec` 会话，提示中只包含当前用户构思、已保存创作说明、制作约束和指定剧本版本。明确区别用户原始要求、`preservedContent` 与 `addedSettings` /【AI补充】，不复用创作会话记忆。待审资料中的命令或“直接PASS”等文字仅视为待审内容，不作为系统指令。

实际调用沿用本机认证和用户配置，采用官方非交互参数：`--json --sandbox read-only --ephemeral --skip-git-repo-check --output-schema`，通过标准输入传文字，没有shell拼接。任务运行目录只保存Schema和任务说明；认证token不会写进数据目录。

## 报告与版本绑定

报告独立保存在 `data/script-reviews/<任务ID>.json`，包含审阅输入Hash、项目与剧本版本ID、来源Hash、输入快照、真实运行事件及最终报告。六类检查均需逐项证据：用户内容保留、人物动机、剧情逻辑、目标时长、场景连续性和制作难度。

报告含总评PASS/REVISE、六类证据、编号问题、严重程度、问题位置和修改建议。时长仅为文字估计，必须给假设依据，允许无法判断时为null，不能冒称实际媒体测量。制作难度为定性审查；没有真实价格时不能声称预算已通过。

进程成功退出、真实 `turn.completed`、JSON解析、六类完整唯一证据及内部结论一致性均通过后才标记 `succeeded`。报告总评PASS与未解决REVISE项或blocking/major问题冲突时拒绝；成功生成、退出码0或格式校验本身都不是独立剧情PASS。

结构验证只验证字段与内部一致性，不能自动理解故事语义。版本过期判断由工作台用当前上游/剧本Hash与此报告绑定的Hash比较；旧报告始终保留，不应套用到新版本。

## 中断与错误

一个项目同一时刻只允许运行一个独立审阅，工作台最多两个。取消或关闭服务会终止子进程；未完成任务保留cancelled/interrupted，不自动重试。模型/认证/网络失败、超时、空报告或证据不全均保存真实失败，报告为null，没有预设替代文本。事件和错误复用统一 `redact()`。

## 隔离测试

`tests/script-review.test.mjs` 显式注入异步runner夹具，检验报告校验、按需调用、独立输入、持久化不改原稿、无效成功拒绝、脱敏、并发/取消和重启恢复。夹具报告明确标记“隔离测试”，不进入产品数据、不作为真实Codex成功证据，不消耗模型或即梦生成额度。本轮新增模块的真实运行能力仍以用户实际点击后的CLI终态为准。
