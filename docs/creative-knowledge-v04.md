# 创作规则与制作流程整合方案（知识库 0.4）

本次把三个 Word 手册、已有导演资料包和 Huobao 拆解转成软件可读取的知识数据与离线提示词编译核心。工作台现有版本仍为 0.2.1；知识库版本 0.4.0 不表示整套软件已升级或完成生图、分镜界面、自动剪辑。

## 创作路线

默认目标调整为：故事构思 → 自有 ChatGPT／Codex 扩写、剧本与分镜候选 → 独立审阅 → 采用版本 → 分镜图 → 即梦画布与无对白视频 → 后期配音、音效、字幕与剪辑。即梦剧本适配保留为可选渠道，不能让它的文字报价缺口阻断未来的 Codex 文字创作。图像和视频各自核实能力、费用与预算。

软件应允许每个岗位选择工具，保留相同的项目、分集、人物、场景和镜头身份。ChatGPT 手工网页协作、官方 CLI 和可选 API 是不同连接器；“已订阅 Pro”“已登录”“不填 API Key”都不是软件已经获得某个图像接口或免费额度的证据。图像连接器必须展示实际可用方式；尚无可验证自动接口时使用导出任务包、人工生成、导入结果的明确路径，不暗中换用付费 API。

## 风格库的组织与优先级

选择层级为“导演 → 具体作品／技法预设 → 当前场景适用规则”。导演姓名用于导航，真正发给模型的是可执行电影语言。每条规则区分原资料可定位内容、软件设计转译、实际生成验证；目前新增规则都是待生成验证的设计候选。

优先级固定为：用户锁定的事实和制作限制 → 镜头叙事目的 → 人物／空间／时间连续性 → 作品级风格 → 模型补充。不能为了预设的雨夜、霓虹或暖色，把用户的阴天傍晚、服装、人物关系改掉。自然语言中的潜在冲突仍需审阅；编译器只能可靠阻断可比较的显式字段冲突。

原资料的作品适用范围不得被新手册例子覆盖。例如《小武》的现场手持与《站台》的远观是不同预设；新提到的参考作品只记为待核实候选。15 条 `case_only` 案例规则默认不启用，显式选择后仍提示适用范围。所有 90 条扩展均需 `manualRuleIds` 明确选择，不自动塞进每个镜头。

提示词与上下文分为四层：

1. 叙事：信息先后、人物目标、观众何时获知，进入剧本／审阅上下文。
2. 静态画面：单一时刻、构图、光线、材质、空间和可见动作，进入 `imagePrompt`。
3. 动态摄影：起幅、路径、速度、落幅、主体与环境运动、独立焦点计划，进入 `videoPrompt`。
4. 后期：剪切、对白、配音、画外音、音乐与字幕，进入后期上下文。前期视频提示词要求无对白／旁白／背景音乐；实际关闭音轨仍由已验证适配器实现。

`appliedRules` 只列出真正写入画面／运动提示词的规则，并注明目标；叙事、声音、验收建议列为 `contextRules`，不冒称已经执行。第一视角是视点，手持是稳定性，光学变焦是镜头变化，均不能直接替代相机位移。复合运镜需要分阶段或明确联动设计。

## 继承 Huobao 的生产逻辑

| 生产对象 | 必须保存 | 修改后的行为 |
| --- | --- | --- |
| 项目／分集 | 稳定ID、输入要求、revision、原始构思 | 修改要求后旧候选和旧审阅需复核 |
| 人物／场景／道具 | 稳定ID、版本、实际附件及内容Hash | 引用必须绑定版本；仅写文件名不等于模型已读 |
| 剧本／镜头 | 原文、候选、人工锁、活动正式版本、来源 | 先校验候选，再原子采用；失败不得清空人工稿 |
| 执行尝试 | 连接器／账号配置ID、岗位、输入Hash、request-id、外部任务ID、原始回执 | 换模型或账号产生新尝试，不重建生产对象、不清零返工次数 |
| 媒体与导出 | 来源镜头、实际路径、校验结果、费用证据、导出规格 | 任务完成和有URL都不能替代画面检查与ffprobe验收 |

六类状态要分别呈现：工具与认证、能力证据、执行、候选、正式阶段、媒体。任务包中的 `valid_draft` 只表示结构与显式声明检查通过。导入的 `PASS` 永远只当作回答文字，不能直接标成正式通过。

四岗位保留为 `drama-topic`、`drama-script`、`drama-visual`、`drama-review`。H01提出生产初验0、纠正复验1／2、最终正式审阅最多2轮；未通过或缺输入的正式审阅也占一次，换路径、模型或账号不得重置。旧记录只能导入可证明的历史下界。**仓库尚缺真实15份正式输入清单、岗位guard及账本格式；本次没有伪造这些接口或宣称接通。** 新核心始终返回 `formalStageStatus: not_checked`。落地时应接入真实工作区，独立保存verify结果、输入Hash和交接证明。

连接器约定：检测与能力声明 → 准备任务 → 连接／断开 → 提交／观察／取消（仅支持者）→ 导入 → 候选采用。手工网页连接器只提供任务包导出与回答导入，不伪装自动提交或后台读取剪贴板。接口能力、用户来源声明和真实服务回执分别保存。

## 本次可运行的部分

`src/creative-design.mjs` 提供：

- `loadCreativeKnowledge(root?)`：加载本地知识数据，给出编译用知识Hash。
- `listStylePresets(knowledge)`：列出17个作品级预设和手册扩展。
- `compileShotDesign(input, knowledge)`：输出两个提示词、来源、锁冲突、参数过滤与状态。
- `buildCreativeTaskPacket(input, knowledge)`：绑定项目／分集／镜头、revision、上游Hash与输入快照，构建 `drama-visual` 包。
- `validateImportedCandidate(packet, candidate, currentContext?)`：只校验导入身份与快照，不保存文件、不采用正式稿、不调用guard。

正式使用时调用方先持久化原始回答，再传可信存储中的任务包。第三参必须来自当前项目存储：项目／分集、revision、上游Hash、当前镜头输入Hash与知识Hash。缺第三参的返回明确为 `packet_matched_only`，不能作为当前版本可采用的依据。无论结果如何都需独立语义审阅。

模型专属参数仅按调用方的已核实白名单输出；白名单是声明，模块不会自行验证服务。`attached: true` 也是调用方声明，实际素材是否发送必须核对执行回执。没有声明支持独立负面参数时，避免项仍作为正向提示词里的约束描述。

离线预览（无需账号、无生成费用，不写项目数据）：

```powershell
node scripts/preview-creative.mjs --list
node scripts/preview-creative.mjs examples/creative/waiting-shot.json
node scripts/preview-creative.mjs examples/creative/waiting-shot.json wong.chungking.city
node scripts/preview-creative.mjs examples/creative/waiting-shot.json anderson.budapest.order
node --test tests/*.test.mjs
```

示例使用同一老人等待场景、相同人物天气锁与真实示例文本Hash，三个预设只改变选择的规则。参考定妆图尚未附加，输出如实提示。预览差异用于比较设计，不能证明图像审美、人物一致性或视频运镜已经达标。

## 下一里程碑与验收

先实现“本机 Codex 文字创作＋导演选择＋分镜候选”闭环，接入现有版本和独立审阅页面；再接实际图像连接器，最后接即梦媒体。不要先扩充数据库规模。

下一批界面需要：我的创作工具、四岗位工具选择、导演／作品级预设、规则来源与勾选、镜头的静态／运动／后期分栏、候选差异与锁、审阅问题和旧版标记。增加 `drama-script` 与 `drama-visual` 的真实 Codex 任务适配，复用已有任务持久化机制，而不是直接拼一条命令绕过候选版本。

该里程碑验收必须包含同一30秒故事、三个镜头、两种预设的规则差异；用户锁不变；真实Codex产生候选并由新会话独立审阅；输入变更拒绝旧稿；重启恢复原任务；不依赖即梦文字报价。浏览器测试与真实调用分别记录。图像、即梦画布导入、视频、后期的费用与能力再各做单独验收。

后续媒体阶段必须绑定实际定妆图／场景图，记录每次生成与返工、只重做选中镜头；先比较可用镜头成本再扩大批量。成片首选可验证的本地MP4导出，剪映草稿／自动化另行确认。不得把设计方案、隔离测试或样例输出写成已经部署的制作能力。
