# 0.10.0：分页剧本与 AI 创作助手

本轮在现有 C·调整版中修改真实剧本页面，完整保留左侧窄图标栏、项目卡片、七步流程及四个工具入口。没有建立独立演示站，也没有通过界面修改打开图片、视频、配音或付费 API。实际测试、截图、真实文字调用及未完成项统一见[本轮验收](script-assistant-v11-acceptance.md)。

开发基线为 PR [#9](https://github.com/499893181-lang/AI-Drama-Studio/pull/9) 的 `codex/ui-c-adjusted-v10-20261116`，提交 `b3a683c5b00017fa66b406ece50205cafd61c3b8`；独立实施分支为 `codex/script-assistant-v11-20261117`。这是保留前序功能的堆叠 PR，不从缺少已有功能的 main 覆盖实施，不自动合并。

## 使用路径

沿用原启动器与 DATA_DIR。默认入口为 [4317工作台](http://127.0.0.1:4317)，本机此次为 [4320工作台](http://127.0.0.1:4320)。剧本路径为 `/creative.html?stage=script&projectId=<项目ID>`，确认后进入同项目的 `?stage=storyboard`。这些是本机地址；GitHub提供源码和公开记录，不远程公开个人数据或认证。

剧本工作区改为点击式四标签：

| 标签 | 用户处理的内容 |
| --- | --- |
| 创作要求 | 填写想保留的内容、节奏和结尾，查看可读设定摘要；结构化字段放高级入口。 |
| 剧本正文 | 生成结果直接成为可编辑草稿，不再要求复制到另一个人工区；候选原文仍保留。 |
| 检查建议 | 点击查看单条问题、依据及建议；不自动改写，旧报告明确提示需要复查。 |
| 历史版本 | 点击选择一个候选或保存版本查看，原稿、来源和编辑历史保留。 |

尚无正文时主操作为“生成剧本”；有正文后为“确认剧本，进入分镜”。确认统一处理完整正文保存、不可变版本、采用指针和分镜来源绑定，避免用户分别点击采用、另存与选为来源。revision 或上游输入不一致时保留当前编辑与旧稿，并要求刷新核对；不会用旧窗口覆盖新稿。内容与当前有效版本相同的重复确认复用版本。

## 点击分页与保存

正文按场景标题、段落和阅读容量分页，提供场景目录、上一页／下一页及页码。分页保留原始 UTF-16 范围、换行和分隔符；编辑某页只替换该范围，切页仍保留修改。保存和确认使用重组后的完整正文，不只提交当前可见页，不截断尾部。选中文字也转换为完整正文的准确位置。分页、场景和镜头均不自动轮播。

分镜保留可点击缩略图，并提供上一镜／下一镜。检查建议逐项点击，历史版本选中后展示；高级 JSON、任务 ID、原始候选与诊断继续可访问，但不作为普通创作的必填步骤。

## 一次创作与独立检查

生成按钮附近说明账号用量：一次剧本创作可串联至多一次新会话独立检查，最多两个 Codex 文字任务，不循环改写或重试。检查绑定实际成功候选或明确保存的正文版本，不能提前把结果采用为分镜来源。创作失败保留原稿；检查失败仍保留完整候选供编辑，并如实展示失败。

用户也可以明确检查当前人工正文。检查先保存非采用的不可变快照，再对该版本运行一次新会话审阅。正文或上游要求变化后，受影响报告标为需要复查；字符来源核验、格式合格与模型审阅意见都不等于史实核验、正式四岗位 PASS 或媒体验收。史实和时代背景问题须有可定位依据，缺少依据时明确待核实。

## 右侧 AI 创作助手

右侧助手支持展开、折叠与多轮文字交流。展开时输入框保持可见，长回复用上一页／下一页阅读；历史消息用上一条／下一条切换，不堆成无限滚动面板。较窄窗口可收起辅助面板，正文仍可阅读。

发送前读取并绑定当前项目、制作步骤、创作要求、完整编辑稿、实际编辑版本、当前采用版本及准确选段。未确认编辑稿与已采用版本分别记录，不能把旧 activeScriptId 当作用户正在看的新正文。选段必须与服务端正文的实际位置、内容完全一致；发送前保存当前编辑稿，普通讨论本身只写项目对话记录。

“把这一段写得更有气势”“缩短到30秒”“保留结尾，调整前面的节奏”等请求先产生建议与修改前后对照。只有点击“应用修改并保存新版本”才更新完整正文、追加待确认 AI 版本，原采用指针不会提前切换；之后再由“确认剧本，进入分镜”明确采用。应用前重新核对原快照 Hash、项目／工作台／编辑 revision、来源、知识与完整正文；旧建议不能覆盖新要求。重复应用返回原版本，不重复保存。

对话完整保存在各项目自己的记录中，刷新可恢复，切换项目不混入其他项目的消息。每次模型请求只携带该项目最近12轮历史，并记录包含的消息及省略数；更早记录仍保留并可点击查看。CLI 每条消息使用新会话，由应用明确提供该项目历史，不复用另一个项目的 CLI 会话。

## 设定、来源与故障边界

人物、场景、道具及镜头结构由内部数据整理，普通用户通过可读摘要、文字及对话处理。AI建议纠正既有实体时保留稳定 ID 和类型，使用新的实体版本并明确 AI 来源及改动说明；原版本、输入证据和旧稿保留。同一历史实体版本标签不能被另一组事实重用。新增设定缺少可定位输入证据时保持 AI 补充或待确认，不能因用户点击应用、确认或下游引用就提升为用户事实。相关分镜、审阅和媒体沿原版本与 Hash 规则需复核。

对话意图及稳定 requestId 先落盘。同一项目已有消息在运行时阻止并发重复发送，重复 requestId 返回原任务，取消、中断和重启不自动重发。真实完成终态、可解析输出及完整回执齐备后才显示成功；认证失败显示待配置，原始结果、错误与可能迟到的回执仍绑定原输入，不能覆盖新稿。

本工程复用本机已登录的官方 Codex 文字通道，以[官方非交互模式说明](https://developers.openai.com/codex/noninteractive)为契约依据，沿用实际 CLI 的 `exec --json --output-schema`、新会话 `--ephemeral` 与 `read-only` 运行方式。没有新增 API Key 或切换额外付费 API。账号用量按实际回执保存；未返回的人民币／积分费用保持未知，不显示为免费。read-only 与文字提示不被宣称为媒体工具严格次数保证；原自动出图入口仍关闭，图片原1/1、媒体认证和预算授权规则不重置。

## 实现和检查入口

主要实现为 [`src/script-workbench.mjs`](../src/script-workbench.mjs)、[`src/creative-assistant.mjs`](../src/creative-assistant.mjs)、原 [`src/creative-store.mjs`](../src/creative-store.mjs) 与 [`src/creative-runner.mjs`](../src/creative-runner.mjs)；界面为 [`public/creative.js`](../public/creative.js)、[`public/script-pages.js`](../public/script-pages.js) 和 [`public/creative-assistant.js`](../public/creative-assistant.js)。工作台、生成及对话记录沿用原 DATA_DIR，个人原文、认证、原始运行回执和完整对话不进入 Git。

新增本地接口位于 `/api/projects/:id/creative/script-workbench`、`script-editor`、`script-generate`、`script-confirm`、`script-check`，以及 `/api/projects/:id/assistant/messages` 的发送、查询、应用和取消；服务端检查真实项目归属及当前版本，不能由客户端任意指定其他来源。

隔离验证命令不会调用真实模型或媒体：

```powershell
node scripts/check-ui.mjs
node --test tests/*.test.mjs
node tests/script-tabs-browser.mjs
node tests/assistant-browser.mjs
```

本轮真实助手验收获准最多两轮文字调用。第一轮完成，正确读取测试项目、步骤、人物和结尾；第二轮确实携带一轮历史和精确选段，但验收脚本的等待竞态提前关闭服务，该轮中断，未取得完整正文或用量回执，未应用建议。没有第三轮。等待 helper 已修正，并以两项隔离回归验证；隔离改稿、版本与应用测试不能冒充第二轮真实改稿已经通过。全部实际结果、证据范围及未完成项以[验收记录](script-assistant-v11-acceptance.md)为准，不把旧版本通过自动套用到本轮。
